**《未送达》数据、微调与评测计划 v1.0**

> 研究与建设目标仍待执行。当前实现与工程回归见 [README](../README.md)，执行优先级见[任务清单](backlog.md)；本文列出的数据不是仓库现有资产。

日期：2026-10-18。本文是待实施的实验设计，所有数量和阈值为目标。示例文件均为合成设计样例，不是已采集数据，不代表真实灾害记录或模型效果。

1. **数据分成知识资料、模型样本和业务演练三层。**

   | 层次 | 具体内容 | 主要用途 | 真值怎么得到 |
   |---|---|---|---|
   | 知识资料 | 公开或获授权的预案、设备手册、开发期案例、演练规则 | AgentArts RAG | 原文、版本和适用条件核验 |
   | 模型样本 | 文字/语音转写与结构化事件；图片与可观察事实 | 抽取微调、多模态组件评测 | 人工标注或由独立场景状态生成标签后核验 |
   | 业务演练 | 图拓扑、资源、随时间变化的可见报告、隐藏状态、消息终端 | 主动核实、调度、端到端系统评测 | 隔离的场景状态及终端实际回执 |

   单一公开灾害数据集不能提供整套站点状态、中文语音和调度真值。所有材料在数据清单中标注 public、authorized、self_recorded、synthetic 或 benchmark，并记录使用条件。

2. **拟定规模与先后顺序。**

   | 数据资产 | 第一阶段 | 比赛版目标 | 说明 |
   |---|---|---|---|
   | 知识文档 | 10 份、50 个开发查询 | 20–30 份、100 个独立人工核验查询 | 文档数量不等于知识覆盖 |
   | 事件抽取 | 先标注 100 条开发样本 | 1,500 训练 / 200 验证 / 300 测试 | 按场景和来源分组隔离 |
   | 图像核验 | 30 张开发样本 | 100 张开发 / 100 张独立测试 | 首版不微调视觉模型 |
   | 语音核验 | 20 段自录短语音 | 60 段开发 / 60 段独立测试 | 不同说话者/场景分组，包含干净与噪声条件 |
   | 端到端场景 | 12 个可公开冒烟案例 | 40 开发 / 20 验证 / 40 盲测 | 场景模板、拓扑与事件组隔离 |

   先用小样本基线验证任务是否成立，再扩充训练集。训练集可由结构化场景生成口语报告并人工核验，不能把语言模型编造的事实直接当成真值。300 条抽取测试样本和 40 个盲测场景均需人工检查。

   语音和图像可以分别评估，不要求每条文字训练样本都附带音频和图片。需要跨模态验证的样本单独登记证据组合关系。

3. **采集与合成过程。**

   先创建结构化场景记录：区域、节点、事件时间、状态、允许公开的信息、故意缺失项和可触发的检查。由这些记录生成报告，记录生成方式。对合成材料，标注员检查语言是否仍然表达预设事实，尤其是“不确定”“刚刚”“昨天”和地名简称。

   自录语音只使用愿意参与演练的成员；保存转写、说话者分组 ID、录音条件和对应原始文本。用于界面的地点采用虚构区域编号，真实试点材料先完成授权与必要脱敏。

   图片来自有适当使用权限的素材或自行拍摄。登记地点、时间的来源；缺少定位或拍摄时间时标签就应是未知。视觉标签限制为可观察事实，例如“图中可见障碍物”，不把它扩大为“道路当前不可通行”。

   公开 CrisisMMD 可用于信息性、灾害图文类别等预实验；其数据卡标示英文图文和 CC-BY-NC-SA-4.0 许可。它不提供本项目的中文语音、乡镇网络或资源调度答案。正式使用时核对原始分发与素材使用条件，商业转化需另审数据许可。

   来源：[CrisisMMD 数据卡](https://huggingface.co/datasets/QCRI/CrisisMMD)。

4. **标注契约。**

   事件抽取目标字段包括：`event_type`、`entity_id`、`location_id`、`occurred_at`、`time_expression`、`facts`、`unknown_fields`、`evidence_spans`、`requires_verification`。

   `facts` 只保存材料支持的主张，允许 `reported_restored` 等显式区分报告与核验结果的枚举。现场一句话“恢复了”并不自动生成终端回执。不能由材料确定的字段设为 null 或 unknown，并把需要核实的字段列出来。

   `evidence_spans` 是原文区间、语音片段或图像位置。数据管道验证这些引用确实存在。地名简称无法唯一映射时保留候选与歧义，不以猜测选择一个位置。

   对同一来源的重复转发分配同一 source group。跨模态冲突标注同一事件和地点下互相不兼容的具体主张，而不是只标“两个输入不同”。

   初期至少双人复核一批样本，记录分歧类型并修订标注规范；难例、未知项和测试标签必须复核。保存原始标签、修改记录及标注版本。

5. **数据划分与防止泄漏。**

   先按场景模板、事件、素材来源和说话者分组划分，再在训练组内扩写和增强。相同照片、语音的不同编码、同一报告的改写和同一场景的时间重排均属于同组。

   对文本、图像和音频做 ID、哈希及近重复检查。数据清单记录 `group_id`、`split`、`source_id`、`license`、`content_hash` 和 `generator_version`。测试样本的改写不能回流训练集。

   RAG 可以包含部署时合理可用的设备和规程知识；不能包含测试场景的故障答案、最优调度方案或未来回执。测试环境中未来事件直到演练时钟到达才可见。

   模型角色只能查询允许暴露的 evidence view。隐藏真值、注入脚本配置、答案标签和评分规则实现由隔离评估端持有。评分指标可以公开，单个场景答案不通过工具提供。

6. **LoRA 微调实验。**

   研究问题：在相同输入、检索资料和解码条件下，领域 LoRA 能否提高中文事件抽取质量，减少把未知信息填成确定事实的错误，同时保持未见场景表现。

   至少比较三组：原始基座加统一提示词；原始基座加少样本提示；同一基座加 LoRA。不要把不同规模模型的差异当成微调增益。

   第一轮候选配置：LoRA rank 8 或 16、alpha 16 或 32、dropout 0.05、学习率 5e-5 或 1e-4、最大序列长度 2048、有效 batch 16、2 个 epoch。它们是拟定试验起点，目标模块、精度、批大小与具体参数字段需按实际模型架构和 ModelArts 训练模板调整，不是平台默认配置或效果保证。

   首先用 50–100 条训练样本做单步/短程兼容性检查，验证数据读取、loss、权重保存及重载。兼容性检查成功只证明训练链路可用。正式训练仅用训练集，验证集选择 checkpoint；最终测试集在配置冻结后评估。

   主要指标：字段 macro-F1、实体/位置精确匹配、时间抽取正确率、JSON schema 合法率、未知字段误填率。误填率的分母为金标要求保留未知的字段数，不能用全部字段稀释。

   每次保存基座、适配器、tokenizer、训练配置、数据清单、种子、日志、验证选点和推理代码版本。普通 CPU 服务器不承担该大模型微调任务；训练资源落实后使用 ModelArts 可用加速资源，最终以实际资源和版本兼容性验证为准。

   正式数据导入前，根据所选平台作业的数据格式把设计样例转换为其支持的 Alpaca/ShareGPT 等具体格式，并跑读取检查。`examples/lora.example.jsonl` 仅展示 instruction/input/output 语义，不承诺可直接用于任意训练作业。

7. **RAG 与多模态组件评测。**

   RAG 的 100 个独立查询拟定覆盖：适用规则 30、设备条件 30、版本/时效冲突 20、知识缺失 20。每条标注支持文档、片段和应拒绝确定回答的条件。测召回、引用支持性、版本适用性和知识缺失时的误答。

   用相同问题比较关键词检索、混合检索、混合检索加重排/适用性处理。检索指标和端到端业务指标分开，不用“有引用”代替“引用支持结论”。

   图像测试测可观察事件识别、证据定位和时间/位置未知保留。语音先测转写字错率或词错率，再测经过完整转写与抽取后的字段质量。不能把人工纠正过的转写结果冒充原始语音端到端效果。

   跨模态组合案例包含一致信息、时间不同、地点不同、同源转发和真实冲突。比较单模态与组合输入，在相同输出任务上评测。

8. **端到端主实验。**

   40 个盲测场景拟分为四组各 10 个：报告缺失/延迟；证据冲突/陈旧；资源/道路/电量约束；链路中断/重复/乱序回执。每组均可包含组合事件，先定义组归属和难度，不能看到方法结果后重新分类。

   所有方法使用相同初始拓扑、资源、事件发布过程、工具权限和 policy。生成场景时记录可行性；本来无解的场景也保留，评测是否正确报告无解，而不是强行要求完成。

   | 方法 | 能力 | 作用 |
   |---|---|---|
   | B0 | 固定规则、相同资源和允许的工具 | 业务参照 |
   | B1 | 单 Agent，相同模型、多模态输入、RAG 和工具 | 检查多 Agent 协作增益 |
   | B2 | 四角色流程及约束求解，关闭主动核实 | 检查主动核实贡献 |
   | M | 完整方法 | 主方法 |

   先在开发/验证场景按统一规则确定最强基线。主方法和最强基线拟在 40 个盲测场景各重复 3 次，形成配对比较。模型随机重复与场景随机性分别登记。实际样本量和调用预算在先导试验核算费用后冻结；缩水或调整必须写入实验记录。

   LoRA、RAG、多模态模块先做独立对照；必要时用冻结的公共场景补充系统消融。MCP 主要验证真实工具调用、版本控制、幂等与互操作，不预设“换成 MCP 协议会直接提高识别精度”。

   每种模型方法统一最大调用数、可用工具、核实资源和总时限。多 Agent 方法多出的调用计入成本，报告实际消耗。失败和超时 episode 保留在总分母中。

9. **业务指标的精确定义。**

   送达率使用预先定义的目标终端/区域集合，不只统计系统选择发送的目标。一个代表终端收到不能扩展为整个村庄所有居民收到。按终端、区域或人口代理加权的指标分别报告。

   `terminal_delivery_rate = 在有效期内实际返回接收回执的目标终端数 / 全部目标终端数`。

   `human_confirmation_rate = 在有效期内显式完成人员确认的目标终端数 / 全部目标终端数`。

   `unknown_region_miss_rate = 在规定核实时窗内未被标为待核实或未触发核实的真实断联区域数 / 真值中断联区域数`。没有断联区域的场景该指标记为不适用，不改成零后混入平均。

   `max_unconfirmed_duration` 为各目标从需要确认时刻到实际确认的最长时间；到时窗结束仍未确认的目标按右删失保留，报告比例并使用统一时窗统计，不能从计算中删除。

   `infeasible_plan_rate = 被独立约束检查发现不可执行的计划数 / 生成的计划数`。同时报告“无可行计划时正确停止”和“错误声称可执行”的比例。

   `probe_cost` 以演练预先定义的核实次数、人员占用或设备占用分别统计。`inference_cost` 以实际 token、视觉调用和语音时长记录，再按账号实际价格核算。

   同时统计已由当前有效证据确认正常的区域仍被错误标为未知的比例，以及已有充分证据时重复请求核实的次数，防止“全部标未知、全部发起检查”获得虚假的优势。真实缺乏证据的区域保留 unknown 是正确行为，不能仅凭隐藏真值中它实际正常就处罚该判断。

   演练分钟与真实墙钟时间分别报告。API 和算法延迟使用真实毫秒；仿真的消息中断/部署时长使用演练时间。不能把仿真加速误写成真实抢修时效提升。

10. **程序核验和结果保存。**

   评估器直接读取消息网关与终端事件、任务状态和独立场景真值。模型生成的“已完成”说明不能作为完成证据。约束校验至少检查资源冲突、前序依赖、道路状态、能源条件、审批版本及有效期。

   对传输重复、网络重试、异步任务重复回调和人员重复点击做幂等检查。程序核验宜以可观察业务不变量验证，不写只复制内部实现的单元测试。

   每个运行目录建议包含：`manifest.json`、`visible_events.jsonl`、`actions.jsonl`、`tool_results.jsonl`、`receipts.jsonl`、`metrics.json`、`report.md`。隐藏真值保存在独立受限位置，模型侧运行目录不提供真值路径。

   manifest 记录代码 commit 或文件树哈希、容器/依赖版本、模型和知识库版本、数据 split、场景生成器、policy、随机种子、预算、时区、真实起止时间、演练时钟设置及 AgentArts Trace ID。

   报告配对指标差值、逐组结果、失败类型和不确定区间；可以使用按场景分组的配对 bootstrap，避免把相同场景的重复运行当成完全独立样本。样本量有限时明确结论边界。

11. **完成标准与对外表述。**

   训练成功、模型格式输出成功、软件集成成功、业务有效性和真实用户价值分别提供证据。最终成绩表中的每个数字都能追溯到运行清单与原始事件。

   未提升的模块也记录结果。若 LoRA 只改善 JSON 合法率，就只声明该项收益；若多 Agent 增加成本但没有稳定业务收益，就调整协作边界并重做独立验证。

   仿真注入、真实软件网络实验和合作方演练反馈分别标注。项目最终可展示“在规定演练模型与测试集合下”的改善，不声称已经验证真实灾害中的救援效果。

12. **可执行设计样例。**

   `examples/incident.example.json` 展示统一事件状态与多源证据；`examples/plan.example.json` 展示仅针对核实动作的计划草案；`examples/lora.example.jsonl` 展示三条抽取目标。

   它们可用于接口契约讨论与解析检查。它们不是正式训练集、盲测集、实际模型输出或已部署系统日志。
