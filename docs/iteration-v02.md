# 未送达 v0.2 · 迭代与验证

日期：2026-10-22。当前交付仍为本地合成演练工作台。本轮围绕结果可信度、方案解释和持续演示体验进行修复，不包含华为平台部署、模型推理或训练。

## 结果可信度

| 原有问题 | 本版行为 | 验证位置 |
| --- | --- | --- |
| 新通知可能继承旧通知的确认 | 按当前通知编号及其目标区域统计，历史回执独立保留 | HTTP：新通知不继承历史确认 |
| 重置复用固定演练编号 | 新编号、请求上下文绑定、事务中检查；旧任务与旧页面不能写新演练 | HTTP 与引擎：重置隔离 |
| 同一幂等键换参数可复用旧结果 | 键与规范化参数摘要绑定；批准校验先于缓存命中 | HTTP：参数冲突、错误批准重试 |
| 核实工具把所有区域当成鹿鸣村 | 按请求区域读取独立合成监测表，保留来源和观测时间 | HTTP：新桥镇仍为拥塞、电量 120 |
| 仅检查摘要不足以证明可执行 | 额外验证任务范围、保障方式、路径、资源、电量、规则与拓扑版本 | 引擎：重算摘要后仍拒绝不合约束的计划 |
| 重复人员回执生成重复核验动态 | 仅首次状态推进写入事件和核验记录 | HTTP：幂等回执与旧通知重试 |
| 较长工具响应只保留截断文本 | 预览有截断标记，完整结果独立持久化并带摘要；内部调用编号独立于 RPC 请求编号 | HTTP 与组件：完整响应、重复请求编号、归档后读取 |
| 同一快照产生新方案后仍可执行旧批准 | 新方案明确替代旧草案和旧批准，保留审批记录，拒绝执行被替代方案 | HTTP：相同快照重新规划后拒绝旧批准 |
| 重试执行或重新研判会把完成状态退回等待 | 按本轮实际回执恢复核验状态，执行重试不新增重复核验动态 | HTTP：完成回执后重试与重新研判 |

数据升级会先备份 v0.1 SQLite 文件，保留历史记录。重置通过同一个事务归档当前演练并创建新演练，历史查询为只读。界面可导出归档 JSON。

## 能检查的方案选择

基线拓扑不变：12 区域、18 路段、2 支队伍。当前模型枚举有限队伍分配，结合 Dijkstra 路径计算，对声明约束内的可行方案排序。

| 方案 | 最晚恢复 | 行程合计 | 设备预留外余量 |
| --- | --- | --- | --- |
| C1，已选 | 44 演练分钟 | 57 演练分钟 | 116 演练分钟 |
| C2，备选 | 53 演练分钟 | 75 演练分钟 | 107 演练分钟 |

界面显示选择理由与六类独立检查。RD14 关闭后，鹿鸣村改经白鹭镇、东桥村，最长预计恢复由 44 变为 51 分钟，旧批准不能执行。

设备剩余 15 分钟时，至少一种可达分配需要 64 分钟，缺口 49 分钟；本版列出约束失败及下一步，并保持无可行计划。电量预算包含运输、部署和 20 分钟预留。移动电源仍作预留资源，未纳入自动分配。

这组值是固定合成场景下的计算结果，不是现场恢复时长、受益人数证明或比赛泛化成绩。

## 现场操作与故事推进

- 故事进度由实际快照、方案和当前通知回执推进；一个区域确认后仍显示其余未完成目标与拥塞区域。
- 收件箱和待发确认按演练、区域、通知保存。切页、重开组件后保留已收到消息，慢响应不能覆盖新区域。
- 操作者点击确认时先入本机待发队列；离线保留，实际补发成功后移除。浏览器持久化失败时明确提示仅保留本次会话数据。
- 刷新请求串行合并，写入后再同步，避免慢快照覆盖新结果。服务不可达时显示断开及保留上次状态。
- 重置有页面内确认、记录计数与归档入口；弹窗支持键盘焦点约束与 Escape。手机增加区域选择器，提升小地图的操作便利性。

## 规则检索与真实技术边界

知识源移至 `docs/knowledge/drill-sop.md`，共 8 条自定义规则。检索采用中文双字切分及 SQLite FTS5 BM25，返回命中词、来源、版本和内容摘要；无匹配不填充无关结果。分数表示词项相关性，不是灾情置信度。

四个角色仍由确定性本地规则执行，未调用大模型。图像/音频完成文件头检查、真实保存及内容摘要，没有自动视觉/语音解析。AgentArts、MaaS、SIS、向量 RAG 与 LoRA 仍待真实接入或训练。

MCP 本地路径实现协议初始化、工具发现和 JSON 工具调用，保留实际 HTTP 行为。无状态 JSON 服务允许不提供 SSE，并需校验请求来源；实现依据是 [MCP 2025-11-25 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。检索排序使用 [SQLite FTS5 的 BM25 实现](https://sqlite.org/fts5.html#the_bm25_function)。这些引用不构成华为平台兼容认证。

## 验证

运行命令：

```powershell
npm run build
npm run test:web
.\.venv\Scripts\python.exe -m pytest tests -q --basetemp .cache/pytest-local
```

本轮最终结果：生产构建成功，**30 项 Python 测试、18 项界面测试全部通过**。可核对[验证摘要](verification-v02.md)及其脱敏机器可读记录；原始 JUnit 留在本机 `artifacts/`。共 48 项，这不是 48 个独立灾害场景或模型能力评分。

后端测试在独立端口、独立 SQLite 上执行；界面测试在 jsdom 内模拟用户点击、切页、离线、迟到响应和重开组件。它们验证业务与交互契约，不代表本轮完成了像素级视觉验收或真实云端联调。本轮未生成新的浏览器截图，`artifacts/` 中的旧截图仍属于 v0.1。

验收时本机服务在 `http://127.0.0.1:8000/?v=0.2` 启动，并完成 HTTP 检查（脱敏记录见[验证摘要](verification-v02.md)）：页面与构建资源返回 200，8 条规则可读取，完整工具响应摘要匹配。现有演练没有重置；重新研判产生了含两组候选比较、六项检查通过的待审草案，原方案和批准记录保留为“已替代”，尚未执行新草案或发送新通知。这是当次运行记录，不代表读者本机已有该演练。

调用列表保留最近 240 条摘要，累计调用数单独计数，完整响应保存在 SQLite。历史列表展示最近 30 场归档；更早归档仍可按已知演练编号查询。旧版调用可能仅有摘要，界面不会为其伪造完整响应。
