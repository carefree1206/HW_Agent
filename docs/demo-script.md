# 三分钟演示：从地图空白到一条确认

用途：现场演示、视频录制和团队彩排。日期：2026-10-22。主线对应 v0.2，平台与模型能力使用事实口径。所有地点、监测、道路和资源均为合成演练，界面时间是演练分钟。

## 演示前准备

安装与启动见根目录 [README](../README.md)。打开工作台，确认版本 v0.2、后端连接正常。需要重新演示时，先通过页面归档并重置；初始应为 12 区域、9 正常、2 异常、1 未知、核实预算 2。不要手工改数据库或提前补写回执。

提前在另一标签页打开 `http://127.0.0.1:8000/?terminal=R12` 可用作现场终端。它与指挥台共享同一演练服务，但接收和确认由终端实际请求产生。投影时放大到能看清未知状态、方案对比和回执；v0.2 暂无新截图验收，录制前需实际检查画面。

### 让故事服务技术展示

每次转折展示一个可检查的机制：沉默对应未知状态，核实对应有限预算，选择对应可行解比较，道路变化对应版本失效，抵达对应独立回执。避免通过夸张人物伤亡或虚构成功数字制造戏剧性。

## 技术加演：选一项即可

**电量不足，约 45 秒。** 归档重置，开始研判，再将便携设备电量降至 15 分钟并重新规划。展示一种最省电可达分配至少需要 64 分钟、缺 49 分钟，无可执行新计划。说明“系统必须能够停止并解释缺口”。若先关闭过道路，数值会变化，不照念基线数字。

**离线补发，约 45 秒。** 已执行场景中，先接收消息，再切换该终端为离线，点击确认；观察待发队列。恢复连接并同步，确认一次且仅一次。已确认过的终端不适合再演示首次离线确认，可选择另一目标或新演练。

**工具审计，约 30 秒。** 在运行记录展开调用，选择较长结果，读取完整响应；对照内部调用编号、RPC 请求编号和内容摘要。旧版调用若只保存摘要，应按界面说明展示，不能补造完整结果。

**历史复盘，约 30 秒。** 重置前确认记录计数，归档后在运行记录查看旧演练。强调旧消息、旧确认和旧批准不会进入新的演练。

## 常见问题的回答

| 问题 | 事实口径 |
| --- | --- |
| 现在接入华为了吗？ | 当前版本没有；首个 P0 任务是已发布 AgentArts 工作流调用 MCP 并产生真实 Trace。 |
| 四个 Agent 真会协商吗？ | 当前是四角色规则流程；平台版将按契约引入角色推理与路由，需与单 Agent 同预算比较。 |
| 图像、语音、RAG、微调在哪里？ | 图像音频目前仅保存校验；规则采用 BM25；自动解析、向量 RAG 和 LoRA 均有任务和验收，尚无完成结果。 |
| 44 分钟是不是实际恢复时间？ | 是固定合成图模型的运输与部署预算，不含真实现场与射频覆盖验证。 |
| 为什么不用大模型直接生成路线？ | 自然语言解释需要可执行约束支撑；求解器和独立校验器负责道路、资源、电量，模型输出也必须受其约束。 |
| 应用价值证明了吗？ | 已证明部分软件机制可运行；用户价值需要专业规则审查、对照试用与独立场景评测。 |
| 国一的技术亮点准备怎么做？ | 聚焦决策影响驱动的主动核实、证据版本与约束联动、独立回执；用同预算对照证明增量，详见任务清单。 |

## 故障时怎样演示

服务断开先恢复服务并查看健康状态；不要把断开前的快照说成实时状态。规划失败先看约束和运行记录，不把失败改成成功。如果现场无法完成真实平台调用，明确演示本地版本并保留失败记录。

视频和答辩包需包含：版本/提交编号、演练初始条件、当前已实现与待实现清单、一次正常流程、一次约束失败、真实调用记录，以及数据与素材来源。平台版完成后另加脱敏 Trace 和平台版本，当前不提前制作其成功画面。
